# AAR — the left eye (iGPU) went dark, window focus broke — 2026-11-16

## What we saw

- `AMD Radeon(TM) Graphics` (9950X3D iGPU, `PCI\VEN_1002&DEV_13C0`) is in **Code 43**
  (`CM_PROB_FAILED_POST_START`): driver `amdkmdag.sys` 32.0.21042.62 loads, then fails to start.
- Every failed start leaves a dxgkrnl live dump `0x1B0` (video miniport failed) in
  `C:\Windows\LiveKernelReports\WATCHDOG`. The faulting address in the 06:14 dump is inside `amdkmdag`.
- Dumps: 11/15 21:48, then 05:57, 05:58, 05:59 (one minute before the 06:00 `0x1E` BSOD),
  06:09, 06:10, 06:11, 06:14, and 06:39 (our own `pnputil /restart-device` test — it reproduces on demand).
- Windows now sees one display (the 5090's). Every failed iGPU start rebuilt the display topology:
  windows on the left-eye monitor jumped and focus was yanked. **That is the "window focus" break.**

## What it was NOT

- **Not the NVRAM writes.** `AMD_PBS_SETUP` still holds stock values (0x48=0x00, 0x49=0xFF, 0x4E=0x02);
  the unattended writes never landed. Snapshot: `%LOCALAPPDATA%\Gaia\AMD_PBS_SETUP-20261116-0638.bin`.
- **Not CSM.** The most common fix online (iGPU + dGPU Code 43 → CSM on kills ReBAR) doesn't apply:
  the 5090 shows a 32 GB BAR1, so ReBAR is on and CSM is off.
- **Not a stale driver state.** A live device restart fails the same way, and so does a full
  disable + enable (06:44, another `0x1B0` dump). No live bandage exists — it needs a cold boot or BIOS.

## Most likely

The manual BIOS changes 40 minutes before the first failure — ReBAR and SVM (IOMMU) newly on.
Raphael-family iGPU reports (isc30/ryzen-gpu-passthrough-proxmox #135) show this iGPU breaking when
ReBAR, UMA size or IOMMU change. Secondary suspect: the same SoC/memory instability behind the BSOD
(the iGPU's memory lives behind the SoC, and VSOC/EXPO is already the crash lead).

## What we did

- Defused the boot partition (moved, hash-verified, restorable from
  `%LOCALAPPDATA%\Gaia\retired\efi-20261116\`): both auto-write `grub.cfg`, `EFI\UMAF\grub.cfg`,
  `gaia-boot-wrapper.efi` (auto-fire), `gaia-auto-surgery.efi`, `setup_var.efi`.
  Removed "GAIA Boot Engine" from the firmware boot order. Windows Boot Manager is first; manual
  tools (modGRUBShell, Smokeless UMAF) remain, human-only.

## Marching order (one BIOS visit — also the crash fix)

1. **Plain reboot first.** The driver started cleanly after the last reinstall; see if a cold start clears it.
2. If still Code 43: BIOS → **SVM off** (keep ReBAR on — the 5090 wants it). Reboot, check Device Manager.
3. If still 43: **ReBAR off** as a test only, to name the culprit.
4. If the iGPU needs memory, set **UMA Frame Buffer** in the BIOS menu by hand — never by offset.
5. Fold in the crash plan: flash BIOS 1401 → 2503 (newer AGESA), then VSOC 1.25 V, then RAM 6200/6000.
6. Meanwhile: the left-eye monitor can run off the 5090 — move its cable.

## Lesson for the organism

Never write firmware by guessed offset, and never make a write fire unattended on reboot.
A read is free; a firmware write needs a human at the keyboard and the board's own menu.
